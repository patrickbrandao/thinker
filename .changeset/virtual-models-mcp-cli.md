Virtual models, part 5 (ADR 0004): virtual models in the MCP server and the `thinker` CLI. New MCP tools `thinker_routing_virtual_list`, `_create`, `_update` and `_delete`, and CLI commands `thinker routing virtual list|create|update|delete|enable|disable` (`--model`, repeatable `--fallback`, `--continue-on-default`; `delete` needs `--yes`). `thinker_routing_status` and `thinker routing status` list the virtual models, and `thinker_routing_test` / `thinker routing test --model <virtual>` report the virtual model and routing reason the request went through. Model params can be addressed by virtual model with the `virtual` field of `thinker_routing_params_get`/`_set` and `--virtual` on `thinker routing params get|set`, both exclusive with the tier selector, through the new `GET|PATCH /api/v1/routing/:agent/virtual-model-params?virtual=<name>` endpoint (scope `virtual:<id>`). The CLI agent skill documents them. `thinker_routing_status` keeps its `enabled`/`reason` verdict for `model: "auto"` (now labeled `status_for: "auto"`) and adds `routes_by_virtual_model` and `active_virtual_models`; when only virtual models can route, `reason` is `auto_not_routable` and `auto_reason` keeps the auto-route cause. `thinker routing status` adds the same two fields. Contract change: in the params view returned by `thinker_routing_params_get`/`_set` and the tier/virtual params endpoints, `tier` is now optional (present when the target is a tier) and `virtual` is set when the target is a virtual model. The params `model` selector (tiers and virtual models, MCP, CLI and REST) now also accepts a route's public id, as `/v1/models` lists it (`<alias>/<model>` for a custom provider), and its bare native id when only one connection of the chain has it; the view adds `public_model` and `public_models`.
