## Atualização: PostgreSQL 18

A stack passa a usar o PostgreSQL 18 (`postgres:18-alpine`, fixado por digest). Na imagem oficial do 18, os dados ficam em `/var/lib/postgresql/18/docker` e o volume `thinker_pgdata` é montado em `/var/lib/postgresql` (antes, `/var/lib/postgresql/data`). Volumes novos nascem com checksums de dados ligados.

A imagem do Thinker não inclui o PostgreSQL: atualizar só a imagem (`docker pull tmsoftbrasil/thinker`) não muda o banco. A troca acontece ao atualizar o `docker-compose.yml`.

Não há migração automática de um volume PostgreSQL 16. Se um volume antigo for montado, o contêiner do PostgreSQL 18 se recusa a subir (`there appears to be PostgreSQL data in ...`), sem apagar nem esconder os dados, e o `install.sh --upgrade` restaura o compose anterior quando a verificação de saúde falha. Para levar os dados de uma instalação com o 16:

1. Com a stack antiga: `docker compose exec -T postgres pg_dump -U thinker thinker > thinker-backup.sql`
2. `docker compose down -v`
3. Atualize o compose e a imagem.
4. `docker compose up -d postgres`
5. `cat thinker-backup.sql | docker compose exec -T postgres psql -U thinker thinker`
6. `docker compose up -d`

As gravações de requisições (volume `thinker_request_recordings`) não entram no dump; faça o backup delas à parte.
