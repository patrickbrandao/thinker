# Thinker 0.1.0

Primeira versão do Thinker, um gateway de LLM open source e auto-hospedado. Parte do snapshot `manifest@6.28.6` de [mnfst/llm-gateway](https://github.com/mnfst/llm-gateway) e passa a evoluir de forma independente, sem obrigação de compatibilidade com o Manifest. A numeração recomeça em 0.1.0 (SemVer).

## Instalação

A única forma oficial de implantação é Docker/Compose:

```bash
docker pull tmsoftbrasil/thinker:0.1.0
```

Imagem multi-arquitetura (`linux/amd64` e `linux/arm64`), base distroless, executada como usuário não-root. Porta padrão: `2099`. As variáveis `THINKER_ENCRYPTION_KEY` e `BETTER_AUTH_SECRET` são obrigatórias, com valores diferentes; o instalador gera as duas. O primeiro administrador usa o token de setup do log (veja abaixo). Documentação: [`docs/usuario/`](../usuario/instalacao-docker.md).

## O que mudou em relação ao manifest@6.28.6

### Removido (mudanças incompatíveis)

- **Identificadores renomeados para Thinker (#21):** as variáveis de ambiente passam a usar o prefixo `THINKER_*` (por exemplo `THINKER_ENCRYPTION_KEY`, `THINKER_ENCRYPTION_KEY_PREVIOUS`, `THINKER_RATE_MAX_REQUESTS`, `THINKER_DISABLE_HSTS`), as novas chaves de agente usam o prefixo `thk_` e os cabeçalhos de requisição passam a ser `x-thinker-*` (por exemplo `x-thinker-tier`; a CLI já envia o novo nome). Os nomes antigos `MANIFEST_*` não são lidos: na inicialização o servidor registra um aviso com o nome de cada variável antiga ainda definida (nunca o valor) e a que a substitui. Se `MANIFEST_ENCRYPTION_KEY` estiver definida sem `THINKER_ENCRYPTION_KEY`, o servidor **se recusa a iniciar**, para não deixar ilegíveis as credenciais de provedores já armazenadas.
  - **Como migrar o `.env`:** renomeie cada `MANIFEST_X` para `THINKER_X` mantendo o mesmo valor (em especial `MANIFEST_ENCRYPTION_KEY` → `THINKER_ENCRYPTION_KEY`), troque `MANIFEST_VERSION` por `THINKER_VERSION` e reinicie. Variáveis que o aviso lista como inexistentes podem ser apagadas. Clientes que enviam `x-manifest-tier` devem passar a enviar `x-thinker-tier`.
- **Sem phone-home:** backend e CLI não enviam telemetria nem fazem chamadas próprias para serviços externos (#70). O dashboard também deixou de fazer essas chamadas (#57).
- **Modo único auto-hospedado:** `MANIFEST_MODE` deixou de existir; há um só modo de operação (#71).
- **Camada SaaS removida:** cobrança, Stripe e limites por plano (#52); lista de espera, CRM, Gemini Free, modelos gratuitos, contagem de estrelas do GitHub e páginas de erro hospedadas (#60); Autofix e o healer Phoenix (#66, #57; linhas antigas com status `auto_fixed` passam a contar como tentativa recuperada, `fallback_error`, e, com mais de uma réplica, pare as réplicas antigas ao atualizar, porque as escritas delas falham depois da migração, #68); a camada SaaS do dashboard (#51).

### Novo

- **Rebranding para Thinker:** nome, logo original (#41), workspaces npm e pacote de versão `thinker` (#110).
- **`THINKER_CATALOG_SYNC`:** sincronização dos catálogos públicos (openrouter.ai e models.dev) pode ser desligada; o documento do OpenCode Go só é buscado quando existe um provedor OpenCode Go (#72). Ver ADR 0003.
- **`x-api-key`** aceito como forma de enviar a chave do agente (#63).

### Correções e segurança

- **SSRF:** aliases de executores locais reservados e URLs base validadas (#103); cabeçalhos de credencial bloqueados nos cabeçalhos extras do Playground (#104), com aviso para cabeçalhos inválidos e sem armazenar valores (#106); cabeçalhos do adaptador têm precedência sobre os do Playground (#107).
- A rota pública de status do setup não sonda mais o Ollama (#113).
- Chat roteado corretamente para os provedores embutidos LM Studio e llama.cpp (#100).
- Uso no mesmo segundo passa a contar nas janelas de limite (#56).
- Alertas de segurança de dependências corrigidos (#55, #65); digests das imagens base e do PostgreSQL 16 atualizados (#47, #48).

### Build e CI

- Workflows de publicação herdados removidos; CI própria com lint, typecheck, build, testes unitários e e2e (PostgreSQL 16, matriz de fuso horário), validação da imagem multi-arquitetura e smoke test com Compose (#44, #112).
- Proteções nos testes e2e contra apagar bancos que não sejam de teste (#69, #111).
- Pipeline de release: tag `v*` publica a imagem `tmsoftbrasil/thinker` (`X.Y.Z`, `X.Y`, `latest`) e cria a release no GitHub (#31).

### Últimos nomes renomeados para Thinker

Nenhum nome `manifest`/`mnfst` visível ao usuário permanece. Não há aliases para os nomes antigos.

- **CLI:** o binário e o pacote passam a ser `thinker` / `thinker-cli`; variáveis `THINKER_URL`, `THINKER_API_KEY`, `THINKER_AGENT_KEY` e `THINKER_AGENT_URL`; estado em `~/.config/thinker/`.
- **Ferramentas MCP:** todas trocam o prefixo `manifest_` por `thinker_` (por exemplo `thinker_routing_test`, `thinker_agent_create`, `thinker_agent_configure`, `thinker_provider_connect`, `thinker_doctor`, `thinker_whoami`). O servidor MCP se identifica como `thinker`.
- **Códigos e motivos de erro:** as mensagens passam a ser `[🦚 Thinker M###]` e o link de cada código aponta para [`docs/erros.md`](../erros.md). Os motivos gravados em `routing_reason` passam a ser `thinker_rate_limited`, `thinker_ip_rate_limited`, `thinker_concurrency_limited`, `thinker_invalid_request` e `thinker_internal_error`; uma migração renomeia as linhas antigas.
- **API de análise:** o filtro `origin=manifest` passa a ser `origin=thinker`, e os campos `manifest_errors`, `manifest_lift_pct`, `manifest_error_code` e `manifest_error_message` passam a `thinker_*`.
- **Cabeçalhos:** apenas `x-thinker-*` (por exemplo `x-thinker-tier`).
- **Implantação:** imagem `tmsoftbrasil/thinker`, porta padrão `2099`, nó do n8n `n8n-nodes-thinker`, telas de OAuth `thinker-oauth-success` / `thinker-oauth-error`. As variáveis de gravação usam o prefixo `THINKER_RECORDING_*` nos templates e o Compose exige `THINKER_ENCRYPTION_KEY`.
- **Seed de desenvolvimento:** o usuário `admin@thinker.example.com` com senha `thinker` e a chave `dev-api-key-thinker-001`.

## Mudanças que exigem atenção ao atualizar

### Retenção das gravações: 30 dias (#28)

A retenção padrão das gravações de requisições passou de 365 para **30 dias**. Ao atualizar, a próxima execução da limpeza diária apaga as gravações com mais de 30 dias. Para manter o comportamento antigo, defina `THINKER_RECORDING_RETENTION_DAYS=365` no `.env`. O valor precisa ser um inteiro positivo; um valor inválido faz o boot falhar. As variáveis `REQUEST_RECORDING_*` foram renomeadas para `THINKER_RECORDING_*` e os nomes antigos não são lidos (o servidor avisa no boot se algum ainda estiver definido).

### `THINKER_ENCRYPTION_KEY` obrigatória, sem fallback (#27)

A chave que cifra chaves de provedores, tokens OAuth e gravações é `THINKER_ENCRYPTION_KEY`, e **não há mais fallback para `BETTER_AUTH_SECRET`**. Ela tem no mínimo 32 caracteres e deve ser diferente de `BETTER_AUTH_SECRET`; sem uma chave válida o servidor se recusa a iniciar, e a mensagem de erro aponta para esta receita.

Quem vinha de uma instalação que usava o fallback para `BETTER_AUTH_SECRET` migra assim:

1. Gere uma chave nova (`openssl rand -hex 32`) e defina `THINKER_ENCRYPTION_KEY` com ela.
2. Defina `THINKER_ENCRYPTION_KEY_PREVIOUS` com o valor antigo, que é o `BETTER_AUTH_SECRET`.
3. Reinicie e espere no log `Secret re-encryption complete` e a linha `Nothing left under an older secret`:

   ```bash
   docker compose up -d
   docker compose logs thinker | grep -i 're-encryption\|Nothing left'
   ```

4. Remova `THINKER_ENCRYPTION_KEY_PREVIOUS` do `.env` e reinicie.

A mesma receita rotaciona a chave no futuro. As chaves de provedores e os tokens OAuth são regravados com a chave nova; **as gravações de requisições não**, e as feitas com a chave antiga ficam ilegíveis (o dashboard as mostra como indisponíveis) até a retenção apagá-las. O `docker/docker-compose.yml` já repassa `THINKER_ENCRYPTION_KEY_PREVIOUS` e `THINKER_ALLOW_SIGNUP` ao container, e o `docker/.env.example` os documenta; basta defini-las no `.env`, sem um override do compose. Veja a [instalação com Docker](../usuario/instalacao-docker.md#rotação-da-chave-de-cifragem).

### Cadastro público fechado e token de setup (#29)

O cadastro público está **fechado**. O primeiro administrador é criado pelo assistente `/setup` e exige um **token de setup de uso único**, impresso no log do servidor enquanto não existe nenhum usuário:

```bash
docker compose logs thinker | grep 'setup token'
```

O token deixa de valer quando o primeiro administrador existe. Depois dele, o cadastro por e-mail e por login social continua recusado (HTTP 403, `SIGNUP_DISABLED`) e o login social só entra em contas já existentes. Instalações que já têm administrador não precisam do token.

`THINKER_ALLOW_SIGNUP=true` é uma válvula provisória que reabre o cadastro depois que o primeiro administrador existe; ela some na v0.3, quando o administrador passar a criar as contas.

**Limitação com várias réplicas:** o token fica na memória de cada processo. Num deploy com mais de uma réplica, o primeiro setup precisa chegar à réplica cujo log imprimiu o token (ou rode com uma única réplica até o administrador existir).

### Outras notas

- `BETTER_AUTH_URL` precisa ser alcançável de dentro do container: a verificação de token do MCP busca o JWKS nela. Veja a [instalação](../usuario/instalacao-docker.md#porta-e-acesso-pela-rede).
- Com `THINKER_CATALOG_SYNC=false`, os custos vêm só dos dados embutidos. Veja [Privacidade](../usuario/privacidade.md).

## Instalação nova (vindo do Manifest)

O 0.1.0 só suporta instalação nova; a recomendação é instalar do zero em vez de reaproveitar uma stack do Manifest. O projeto Compose, o usuário e o banco do PostgreSQL agora se chamam `thinker`, então os volumes são novos (`thinker_pgdata`, `thinker_request_recordings`) e os dados antigos não aparecem. As variáveis de gravação `REQUEST_RECORDING_*` passaram a ser `THINKER_RECORDING_*`; os nomes antigos não são lidos.

## Limitações conhecidas

- Templates em `deploy/` são mantidos pela comunidade e não são testados na CI.
