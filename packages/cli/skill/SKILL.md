# Operating Thinker from the CLI

## Overview

`thinker` manages Thinker, the LLM gateway. Every call routed through a Thinker agent gets model routing with fallbacks, per-agent cost attribution, and a request log — for free. Default practice: never hand an app or automation a raw provider key; give it a Thinker agent.

Commands emit JSON on stdout (human hints on stderr) — except `agent env`, which prints dotenv lines by design — exit 0/1, and never block on prompts when credentials come from flags or env. Full surface: `thinker --help`.

Thinker is self-hosted: with no `--url`, `THINKER_URL` or stored login the CLI targets `http://localhost:2099`, and it never falls back to a hosted service. Agent keys start with `thk_`.

## The flow

| Step                | Command                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Auth (human)        | `thinker login` — browser, one click, 30-day sliding token                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Auth (script/agent) | env `THINKER_URL` + `THINKER_API_KEY` — no login step                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Provision           | `thinker agent create --name X --platform <p> --if-absent` → response includes `setup` (the platform's config block)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Check connections   | `thinker provider list [--agent X]` FIRST — the provider you need is often already connected. A connection is only usable if `cached_model_count` > 0; `is_active: true` with 0 models is hollow — run `thinker provider refresh [<provider>]` (re-runs discovery tenant-wide, prints the new counts); still 0 means a bad credential, so reconnect, don't route on it                                                                                                                                                                                                                                                                                 |
| Connect provider    | `thinker provider connect xai --auth-type api_key --credential-env KEY` · `provider catalog` lists all 30+ with auth types · subscription auth opens a browser (impossible headless — reuse an existing subscription connection instead) · own gateway: `provider custom add --name gw --endpoint <url>`                                                                                                                                                                                                                                                                                                                                               |
| Route               | `thinker agent configure X --models primary,fb1,fb2 --provider p [--auth-type a]` — first model is the route, the rest are fallbacks, and the whole chain rides the one `--provider` you name (cross-provider fallbacks are dashboard-only) · add `--tier deep` to upsert a custom tier callers select per-request with header `x-thinker-tier: deep` · for harnesses that pick by model name instead (Claude Code, the VS Code Copilot picker), `thinker routing virtual create X --name deepseek/flash --model deepseek-chat [--fallback m ...] [--continue-on-default]` makes a virtual model the harness sends as `model` and sees in `/v1/models` |
| Verify              | `thinker routing test X [--model <virtual>]` — one real request through the platform's actual API surface; broken routes fail loudly; with a virtual model name the output adds `virtual_model` and `routing_reason`. It writes real rows to the request log — count them in later audits                                                                                                                                                                                                                                                                                                                                                              |
| Wire the app        | deployed → `thinker agent env X >> .env` (one .env per service — the lines always name `THINKER_AGENT_KEY`, so appending two agents to one file silently keeps only the loader's winner; for several agents in one process use `thinker run --agent X --env ROLE_KEY -- <cmd>`)                                                                                                                                                                                                                                                                                                                                                                        |
| Observe             | `thinker requests get --agent X [--status failed]` — paginated; pass `next_cursor` back for the next page                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

Namespace = scope: `provider *` acts tenant-wide, `agent *` acts on one agent, `routing *` holds readouts and the custom-tier and virtual-model lifecycles.

## Gotchas `--help` cannot tell you

| Symptom                                                                                      | Reality                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Proxy returns HTTP 200 but the "answer" starts with a `[🦚 … M###]` tag                      | An error wearing an assistant costume — check the content, not the status. `routing test` unmasks these automatically                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `cost: "0.000000"` on subscription-auth traffic                                              | Flat-rate subscription: per-request cost is genuinely zero, not broken billing                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `agent configure`'s echo differs from later reads                                            | Mutation bodies echo raw API rows — the canonical readback is `routing status <agent>`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| "Which requests used a fallback?"                                                            | Those fields are trimmed from default output — `requests get --full`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 401s missing from the request log                                                            | Rejected-auth attempts are never recorded (no tenant to attribute them to); a leaked key's blast radius cannot be proven from the log                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `THINKER_AGENT_URL`                                                                          | Already ends in `/v1` — append `/chat/completions` directly                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Model prices needed before any agent exists                                                  | `thinker model prices [--provider <p>]` — install-wide, no agent needed (`models <agent>` is the per-agent routable set)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Auditing escalation traffic by `routing_tier`                                                | Custom-tier requests log `routing_tier: "standard"` — the tier identity lives in `header_tier_name`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Route resolves but requests fail on one connection                                           | A connection can be `is_active: false` while a sibling auth-type works — pass `--auth-type` explicitly when a provider has several connections                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Every command answers `Invalid API key — Run thinker login` under env auth                   | Not always an auth problem: a wrong `THINKER_URL` (dead or different install) answers exactly like a bad key. Run `thinker doctor` — it checks config, host, credential, connections and agents in that order, so it separates "host is dead" from "key is wrong for this host" — and never tells you to re-login on an env key                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Need a different reasoning effort, temperature, or other model param without editing the app | `thinker routing params get X [--tier t \| --virtual v] [--model m]` lists what the routed model accepts and what is saved; `thinker routing params set X [--tier t \| --virtual v] [--model m] --set reasoning.effort=high [--unset temperature]` saves it. `--tier` and `--virtual` are exclusive (a custom tier and a virtual model may share a name). `--model` takes the id `/v1/models` publishes (e.g. `<alias>/<model>` for a custom provider), the stored id, or the bare native id when only one connection of the chain has it; the output lists both `models` and `public_models`. Saved params **override** what the app sends, per tier or virtual model and per model (a fallback keeps its own), but only on requests Thinker routes: `model: "auto"`, a virtual model name, or a matching custom-tier header. A request naming a concrete model skips them. Routes a virtual model borrows with `--continue-on-default` use the default tier params |
| `agent configure` / `routing custom create` reject a model as undiscovered                   | Both validate against the agent's _discovered_ models, and a connection with `cached_model_count: 0` contributes none: run `thinker provider refresh` (stale or empty catalog), or pass `--force` — the backend still routes uncatalogued models through provider-qualified passthrough                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| A virtual model name equals a real model id, or requests for it get `M301`                   | An enabled virtual model **shadows** the real id of the same name (ignoring case): the harness gets the virtual chain, never the real model; `routing virtual list X` shows it under `shadows`, and `routing virtual disable` restores the real id. `M301` means no route of the chain (nor of the Default chain with `--continue-on-default`) is available: a virtual model never falls back silently to `auto`. Unlike `agent configure`, virtual-model routes are validated server-side (400 on a model the agent cannot route), with no `--force`. An empty `default` route does not mean the harness cannot route: `routing status` reports `routes_by_virtual_model` and `active_virtual_models` for requests that name a virtual model (the MCP `thinker_routing_status` verdict `enabled`/`reason` is for `auto`, with `reason: "auto_not_routable"` when only virtual models route)                                                                         |

## Common mistakes

- Handing an app a raw provider key — it loses fallbacks, cost attribution, and the log. Create an agent and use `agent env`.
- Verifying a route with hand-rolled `curl` — fake-200s read as success. Use `routing test`.
- Slurping the whole request log — pagination is one page per call by design; loop on `next_cursor`.

Also on the surface when needed: `thinker doctor` (first stop when anything is wrong), `agent setup <name> [--reveal]` (setup block anytime; key masked unless revealed), `agent key path|show`, `agent provider enable|disable <agent> <provider>`, `agent rotate-key` (revocation is instant), `thinker models <agent> --cost --capabilities`.
